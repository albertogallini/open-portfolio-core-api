
# Performance Daily Pipeline – Data Model Documentation

> **Purpose**:  
> Convert **daily holdings + prices + transactions** into **daily performance metrics** (PnL, returns, income, FX effects) at the **position level**, with optional classification.

---

## 1. INPUT DATA MODEL

### 1.1 Daily Holdings Files (Priced Positions)

These are **per-ticker CSV files** generated by `fetch_portfolio_prices()` in the position imputation step.

| File Pattern | `daily_<TICKER>.csv` |
|--------------|------------------------|
| Location | `filesystem_folder/` |
| Example | `daily_AAPL.csv` |

#### Required Columns

| Column | Type | Description |
|--------|------|-----------|
| `date` | `date` (`YYYY-MM-DD`) | Valuation date |
| `ticker` | `str` | Yahoo Finance ticker |
| `isin` | `str` | ISIN (for traceability) |
| `security_type` | `str` | e.g., `Common Stock`, `Currency` |
| `market_sector` | `str` | e.g., `Equity`, `FX` |
| `quantity` | `float` | Position size (shares, units) |
| `ccy` | `str` | Instrument currency |
| `Close` | `float` | **Raw** closing price (not split-adjusted) |
| `FX_RATE` | `float` | `instrument_ccy → base_ccy` (e.g., `EURUSD=X`) |
| `Dividends` *(optional)* | `float` | Daily dividend per share |
| `Stock Splits` *(optional)* | `float` | Split ratio on that day (1.0 = no split) |

> **Note**: All prices are **raw** (not adjusted). Splits are handled via `Stock Splits` column.

---

### 1.2 Transactions File (`_transactions_tickers.csv`)

| Source | Generated by `generate_transaction_file()` |
|--------|---------------------------------------------|

#### Required Columns

| Column | Type | Description |
|--------|------|-----------|
| `tr_date` | `date` | Trade execution date |
| `buy_sell` | `str` | `'B'` = Buy, `'V'` = Sell |
| `quantity` | `float` | Number of units |
| `price` | `float` | **Execution price** in instrument currency |
| `ticker` | `str` | Resolved Yahoo ticker |

> Used to compute **transaction PnL** on trade date.

---

### 1.3 Configuration Parameters

| Parameter | Type | Description |
|---------|------|-------------|
| `prefix` | `str` | File prefix: `daily_` (for multi-file) or full path |
| `holdings_files` | `list[str]` | List of `_daily_<ticker>.csv` files (if multi-file mode) |
| `transactions` | `pd.DataFrame` | Filtered transaction DataFrame |
| `start_date`, `end_date` | `date` | Performance window |
| `classification` | `list[str]` | Optional: `['GICS_Sector', 'Region']` |

---

## 2. OUTPUT DATA MODEL – `DAILY_PERFORMANCE`

> **File**: `<output_name>_daily_performance.csv`  
> **Granularity**: One row **per ticker per date**

---

### 2.1 Core Position & Market Fields (Inherited)

| Column | Type | Source |
|-------|------|--------|
| `date` | `date` | From holdings |
| `ticker` | `str` | — |
| `isin` | `str` | — |
| `security_type` | `str` | — |
| `market_sector` | `str` | — |
| `quantity` | `float` | Forward-filled |
| `ccy` | `str` | — |
| `Close` | `float` | Forward-filled |
| `FX_RATE` | `float` | Forward-filled |
| `Dividends` | `float` | 0 if missing |
| `Stock Splits` | `float` | 1.0 if missing |

---

### 2.2 Market Value Fields (Local & Base CCY)

| Field | Formula | Description |
|------|--------|-----------|
| `mktvalue_lcl_ccy` | `quantity × Close` | EOD market value in **instrument currency** |
| `mktvalue_bod_lcl_ccy` | `prev_quantity × prev_Close` | BOD market value (local) |
| `mktvalue_eod_lcl_ccy` | `prev_quantity × split_adj × (Close + Div)` | EOD value **including dividend & split** |
| `mktvalue` | `mktvalue_lcl_ccy × FX_RATE` | EOD in **base currency** |
| `mktvalue_bod` | `mktvalue_bod_lcl_ccy × prev_FX` | BOD in base currency |
| `mktvalue_eod` | `mktvalue_eod_lcl_ccy × FX_RATE` | EOD in base currency |

---

### 2.3 PnL Breakdown (Local & Base CCY)

| Field | Formula | Description |
|------|--------|-----------|
| `pnl_lcl_ccy` | `mktvalue_eod_lcl_ccy − mktvalue_bod_lcl_ccy` | Total PnL in **local currency** |
| `income_pnl_lcl_ccy` | `prev_quantity × split_adj × Div` | Dividend income |
| `pnl` | `mktvalue_eod − mktvalue_bod` | Total PnL in **base currency** |
| `income_pnl` | `income_pnl_lcl_ccy × FX_RATE` | Dividend PnL in base currency |

---

### 2.4 Transaction PnL (on Trade Date)

| Field | Description |
|------|-----------|
| `transaction_pnl_lcl_ccy` | `(EOD_value − Trade_value)` for buys; `(Trade_value − EOD_value)` for sells |
| `transaction_pnl` | `transaction_pnl_lcl_ccy × FX_RATE` |
| `total_return_basis_lcl_ccy` | **Cumulative absolute trade value** on trade date (used as denominator) |
| `total_return_basis` | `total_return_basis_lcl_ccy × FX_RATE` |

> Only populated **on trade date**. Zero otherwise.

---

### 2.5 Return Components (1-Based)

> **All returns are `1 + r`**, so compounding works with `prod(returns) - 1`.

| Field | Formula | Description |
|------|--------|-----------|
| `return` | `1 + pnl / total_return_basis` | **Total return** in base CCY |
| `return_lcl_ccy` | `1 + pnl_lcl_ccy / total_return_basis_lcl_ccy` | Local currency return |
| `ccy_return` | `return − return_lcl_ccy + 1` | **FX return component** |
| `return_hlds` | `1 + (pnl − transaction_pnl) / position_basis` | Return on **existing holdings** |
| `return_hlds_lcl_ccy` | Same in local CCY |
| `transaction_return` | `1 + transaction_pnl / total_return_basis` | Return from **new trades** |
| `transaction_return_lcl_ccy` | Local version |

---

### 2.6 Return Basis Fields

| Field | Description |
|------|-----------|
| `position_basis_lcl_ccy` | BOD market value in local CCY |
| `position_basis` | BOD market value in base CCY |
| `total_return_basis_lcl_ccy` | Cumulative **absolute** cash flow (trade value) |
| `total_return_basis` | Same in base CCY |

> Used as **denominator** for return calculations.

---

### 2.7 Classification Fields (Optional)

| Field | Example |
|------|--------|
| `GICS_Sector` | `Information Technology` |
| `Region` | `North America` |
| `AssetClass` | `Equity` |

> Added from input holdings if `classification` list provided.
